This document serves as a master guide for any AI agent activities that takes place in this working directory.

- Any parameters for scripts are to be stored in a csv file and loaded using pandas.
- Script name, folder name, and figure name should be descriptive and long, and clearly indicate the contents of the script or folder or figure.
- Any codes should be written in a way that it is easy to understand and maintainable. This includes proper comments and docstrings.
- Generally, one script should only produce one output. If a workflow naturally produces multiple figures or datasets (e.g. one for each region or metric), it must be split into separate scripts that each produce one output. Production loops that iterate over inputs must be written in `main.py` (which orchestrates the sub-scripts using `subprocess`), driven by a parameter CSV file. The output of each script should be saved in the `figures/` symlink folder that has a folder tree structure and file name that mirrors the original script that produces that output. To separate results by iteration, save them in sub-folders corresponding to the parameter value (e.g. `figures/step4_PCA_analysis/21_calculate_pca/.../tokyo_bay/`).
- Scripts should contain the main logic of a certain process. Then the script should be run based on the parameters file. This ensures reproducibility of the outputs by just changing the parameters to do the same process but with diferent parameters.
- The name of output processed data and figures should include the parameters specified in the parameters csv file. This will make it easier to track the results of a script based on what parameters were used.
- Notebooks can be run as a script using the agent_notebook_utils.py. This can also enable modularity to extract and run only the required function.
- Paths shouldn't be hardcoded in scripts or notebooks. Instead, use the ProjectPaths class defined in scripts/paths.py.
- The notebook and scripts within the main pipeline steps folder should be numbered based on the order of execution. The numbering should use the 10's place for the main sub-steps within that module (e.g., 10, 20, 30). If a sub-step generates multiple outputs or its code becomes too long, it must be broken down into sub-sub-steps using the 1's place (e.g., 11, 12, 13, 21, 22, 23). The sub-steps should always be modular and should be able to run independently of each other.
- One script within the step folder module should generally contain only up to 500 lines of code. If the contents get significantly longer, break it down into multiple sub-steps based on the functions. 
- The contents in the step0_sandbox folder should not be cleared. This folder acts as a personal history log and should never be cleaned automatically. The user will manually remove files from this folder if needed.
- If a step in the pipeline outputs processed data, then the output should be stored in the `data/processed` folder and ".dvc" file should be tracked using dvc. Use the same naming convention as the names for the figures output file and folders.
- The scripts in the pipeline should only contain the chunks to create the new folder in the'figures/' path if the script contains a code to create a visualization figure.
- To prevent clutter and orphaned files when naming conventions change, scripts that generate outputs (figures or processed data) MUST clear their specific target output directory (e.g., using `shutil.rmtree(DIR, ignore_errors=True)`) before recreating the folder and saving new files.
- If you need to rename a main pipeline step directory (e.g. `step1_data_extraction` to `step1_data_cleaning`), DO NOT rename it manually. Use `python admin_scripts/rename_pipeline_step.py --old_name "old" --new_name "new"` to safely migrate source code, processed data, figures, and automatically update `dvc.yaml` and documentation.
- If you need to completely delete a pipeline step directory or script, use `python admin_scripts/delete_pipeline_step.py --target <path_to_step_or_script>` to safely remove the source code and its corresponding output files in `figures/` and `data/processed/`.
- If a script or pipeline folder was manually deleted, you can clean up any orphaned output files by running `python admin_scripts/clean_orphaned_outputs.py`.
